# M67 Security Coverage Closure

## Scope and result

M67 is an internal repository-security coverage milestone. The canonical
[`threat_coverage.json`](threat_coverage.json) expands the prior manually maintained map from
13 rows (11 `Strong`, 2 `Partial`) to 36 components with final states of 24 `covered`,
12 `deferred`, and 0 `partial`. The generated [`COVERAGE_MAP.md`](COVERAGE_MAP.md) is the
human-readable projection of that authority.

Threat-manifest schema 1.1 makes every suite claim a single relation from suite to exact case,
fixture, pass/fail expectation, and exact expected-failure set. A positive case cannot prove a
rejection check, and an existing but unrelated check cannot be attached to a negative case.
Direct evidence resolves through Python's AST to exactly one top-level `test_` function;
comments, strings, aliases, and helpers do not count. This structural check establishes test
identity, not arbitrary semantic intent. Protocol-observable rows cannot be closed with
documentation alone. Deferred rows identify a permitted deployment or ecosystem class,
specific rationale, owner, and residual boundary.

## Added protocol-observable cases

- `SP-03`: a byte-identical valid prefix of the signed mediated path, rejected only for the
  suite-declared required-flow truncation check.
- `CN-13`: a later declaration removes the mediated profile and a stale proposal attempts to
  select it, rejected only by the CAPNEG profile-negotiation check.
- `ENF-03`, `ENF-04`, and `ENF-05`: target mismatch, wrong verdict reference, and unauthorized
  verdict cases with exact owning failures.
- `OR-03`, `OR-04`, and `OR-05`: positive `ACCESS_DENIED`, `TOO_LARGE`, and `REDACTED`
  mechanisms; `OR-06`: object-hash mismatch with an exact owning failure.
- `AL-03`: a valid ALERT flow whose only semantic mutation is an unregistered recommended
  action, rejected only by `AL-ALERT-ACTIONS-01` after message hashes are regenerated.
- `SP-04`: the selected signed ALERT path with only the ALERT signature bytes invalidated;
  message hash, object hash, chain, and every other signature remain valid, so the only raw
  failure is `CT-SIGNATURE-VERIFY-01`.

The associated cases are also consumed by the applicable Tier-1 evidence targets so ordinary
conformance and evidence evaluation share the same behavior.

## Evidence authority

`AICP-EVIDENCE-TCK-1.11.0` is the current strong-eligible Evidence TCK. It retains report
schema 2.2 and live trace v4, carries six targets, and has 32 producer and 82 consumer cases
across its three product-profile targets. Exact Evidence TCK 1.10 remains historical and
strong-eligible. Its release record, snapshot, runner-bundle manifest, and bundle digest are
frozen by regression tests.

Two reviewed Evidence 1.10 regression vectors were generated by executing the pre-M67 tree at
`f3a7ea279575da9ea675997850b33483548c013b`: Mediated Blocking has SHA-256
`8d83ea15e8787170f6181e2e5ff3a1e242bd70ae6c52ceb28ee8bd7f942a0c46`, and Resumable
Sessions has SHA-256
`ffa81932f8330c47b9fe78d54ae2708457678c4a58db6f0f30f8998ea9295980`. The current generalized
`report_evaluator.evaluate_report` returns `eligible` for both exact reports. They are
repository external-test adapter vectors, not real independent adoption.

The correction pins the Evidence 1.11 release record, snapshot, runner manifest/bundle,
report schema, and all six target-catalog digests. Neither `AL-ALERTS-0.1` nor
`SIG-SIGNED-PATHS-0.1` is a required suite of those six targets, so adding AL-03/SP-04 does not
change Evidence 1.11 bytes and does not justify Evidence 1.12.

M67 does not modify the Product-IUT or Pairwise TCK release lines. Pairwise TCK 1.3 remains
the current publication-eligible pairwise authority, and no Pairwise TCK 1.4 is introduced.

## Assurance boundary

This closure records executable internal coverage and explicit deferrals. It does not claim
that the arbitrary-secret classification problem, operational rate/size policy, key custody,
endpoint security, product correctness, ecosystem adoption, or an independent security review
has been solved. The canonical repository-truth fields remain
`external_independent_review_completed: false`, an empty external-review artifact list, and
zero externally demonstrated pairwise relations.

Future independent work starts from [`EXTERNAL_REVIEW_HANDOFF.md`](EXTERNAL_REVIEW_HANDOFF.md)
and must satisfy [`external_reviews/README.md`](external_reviews/README.md).
